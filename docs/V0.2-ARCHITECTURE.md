# v0.2 运行时安装与参数自适应设计

## 运行时安装链路

1. 从 `https://api.github.com/repos/ggml-org/llama.cpp/releases` 获取近期正式 Release。
2. 仅展示名称符合官方 Windows x64 二进制规则的 ZIP 资产。
3. 根据本机 GPU 厂商推荐 CUDA 12、Vulkan 或 CPU；用户可以选择其他版本和后端。
4. CUDA 主包自动查找同 Release、同 CUDA 版本的 `cudart` 资产。
5. 所有文件先下载到 `runtimes/.installing-<id>` 临时目录。
6. 官方资产包含 `sha256:` 摘要时必须校验；不匹配即停止。
7. 解压时把每个目标路径规范化并确认仍位于临时目录内，阻止 ZIP 路径穿越。
8. 只有找到 `llama-server.exe` 后，临时内容才移动到版本目录并写入配置。

安装失败不会删除、覆盖或切换当前正在使用的运行时。手工选择已有 `llama-server.exe` 始终可用。

## 自适应输入

- CPU 名称与逻辑处理器数量。
- 系统物理内存。
- GPU 名称、最大单卡显存与 NVIDIA 驱动信息；无法可靠取得显存时按未知处理。
- GGUF 文件大小、架构、原生上下文、层数、嵌入维度、注意力头、KV 头和当前权重量化。
- 用户目标：快速、均衡或极限。

解析器只读取 GGUF 文件头与关键元数据；遇到大型 tokenizer 数组且已取得核心字段时立即停止，不读取张量区。

## 自适应输出

- `--ctx-size`
- `--n-gpu-layers`
- `--cache-type-k` / `--cache-type-v`
- `--fit` / `--fit-target`
- `--threads`
- `--batch-size` / `--ubatch-size`
- Flash Attention 开关
- 下一次选择 GGUF 时的模型权重量化建议

KV Cache 量化是运行参数；GGUF 权重量化是模型文件属性。v0.2 不会在启动时重写或重新量化用户模型。

## 风险控制

推荐器按模型文件大小估算权重占用，并用层数、嵌入维度和 GQA 比例估算每 token KV Cache。结果按安全档位预留系统内存，再下调到 2K、4K、8K、16K、32K、64K、128K 等可解释级别。对于 MLA、混合注意力和元数据缺失的模型，估算可能偏保守，因此始终启用 llama.cpp 的 `auto + fit` 作为运行时二次保护。
